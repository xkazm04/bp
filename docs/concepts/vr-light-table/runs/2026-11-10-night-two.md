## The security review of the table link (02:00, read-only) and S3's fixes (`a31faf1a`)

| Finding | Severity | Fix |
|---|---|---|
| An APPROVE from the headset ran any pending card (release builds, stop-ship waves) | high | An approve from the table must fit what a table grant could cover (four tools, one product, tier 1 or milder), else 403 and the card waits for the PC; a decline is always allowed |
| The door dropped the speech consent header | broken | Forwarded on `listen` only |
| Companion turns uncapped per device | medium | One turn in flight and 6 a minute per paired device (429 past it) |
| Cards from a device-driven turn ran under wide PC grants | medium | They run at once only under a grant the table itself could have made; otherwise they wait for a person |
| Voice budget and answer cache unbounded | medium | 30,000 fresh characters of speech and 1,800 s of listening a day per device; the answer cache capped at 256 MiB |
| Pairing codes in the server log with a paste-ready approve line; no Host check | medium | Codes leave the log; one open request per peer; the door checks `Host`; 32 connections, 8 in flight per peer, head 10 s, request 60 s |
| A finding with no tier passed a tier floor | low | Counts as tier 0 |
| The pairing registry was re-read per request | low | Parsed again only when the file changed |
| `shown` accepted bidi and format characters | low | Refused (400) |

Clean in the review: the pairing nonce and claim, token storage and compare, the allow-list grammar, CORS, policy fields,
shots path traversal. A separate crash review of the night's C++ found lifetimes, threading, indexing and idle cost clean,
and four stuck states plus one off-thread module load, fixed in `bf1a56fa`.

Gaps left open (recorded in `table-link-v2.md` section 12 and `voice-link.md`): a `standup`-only pairing's turn can still
have the agent start a scan; a device's turn text may be 8000 characters; the turn caps live in server memory; the shared
MP3 voice cache is uncapped; callers without a pairing share one `local` voice budget; the token travels in cleartext over
Wi-Fi and sits in plain text in the app's storage; the speech consent is recorded on the headset only; capture goes to a
cloud speech service (no local recogniser yet).

## The unattended bench, in five lines

1. Headset on USB, still on the desk, lock screen off: `adb shell am broadcast -a com.oculus.vrpowermanager.prox_close` keeps the display awake (at night also `adb shell setprop debug.oculus.guardian_pause 1`; back to 0 after).
2. `adb shell am start -n com.developersblueprint.vr/com.epicgames.unreal.GameActivity`, wait about 25 s; check `pidof` and the top activity before trusting a number.
3. Console commands go in as `adb shell am broadcast -a android.intent.action.RUN -e cmd "'<command>'"`: `bp.Tour 0`, `BpTour.Stop`, `BpLevel.Home`, then `BpView.Bench` (Development APK only) to render the seated view.
4. `adb logcat` VrApi lines give App GPU ms and fps; each toggle is bracketed by its own baselines; `adb exec-out screencap -p > shot.png` returns both eye buffers.
5. It measures and shows rendering only: it cannot judge hands, controllers, comfort, audio or passthrough.
