## Repo law

- Read `README.md`, `docs/blueprint-ui.md` (the UI contract: levels of detail, 12 px text floor, performance rules, lenses as data) and `docs/standard/app-structure-v3.md` before changing either surface.
- Lenses are data: a lens is a manifest with fields and JSON health rules. No lens-specific code paths.
- All product data is sample data (*Kettle*). Fixtures are regenerated by scripts in `scripts/`; never hand-edit a generated file.
- Never stage, never stash. Only the Director touches the git index.
- The model and chrome still carry Kettle-only tables (`apps/web/src/lib/model/constants.ts`: WING_DEFS, GA_MILESTONE, LATER_MILESTONES, BLAST_DEFAULT; Dock steering; the search placeholder). Any work that makes bp show another product must grep them and say how each behaves for a non-Kettle product.
- `next dev` writes AGENTS.md into the checkout it runs in; delete it before handback, never commit it.
- A design that spawns a skill headless must verify, before the first real run, that the skill AND every sibling it reads by relative path (lens-scan reads ../scan-sweep) resolve at user scope; a missing sibling silently skipped Opus judgements on 2026-10-14, after a missing lens-scan link on 2026-10-13.
- Before trusting any real product's lens readings, check its context map's COVERAGE of tracked source (files claimed / files tracked, per UI and code root), not its dead paths: paypal 326 of 922, athena 111 of 257 desktop files; every static metric and judge inherits the gap. Personas owns those maps (rescan through its dev-tools API, project-populate contexts lane).
- Building a worktree: Turbopack refuses the node_modules junction; build from the main checkout root with `NEXT_DIST_DIR=.next-<x> npx next build .claude/worktrees/<wt>/apps/web` (and revert the tsconfig include it adds).
- A server under test must be the new build: stopping a background `npx next start` task leaves its node child holding the port, so free the port by its owning PID and probe a route or string only the new build has before trusting a screenshot (stale servers misled runs on 2026-10-13 and 2026-10-14).
- Live products (`?product=<slug>`) are smoke-tested on a real store (`node scripts/scan-demo.mjs` at minimum, a real repo when one is listed) before ship: fixture-green packages never cross the store/route/UI seam.
- Never create two files whose names differ only by case (`marks.ts` beside `Marks.tsx`): Windows resolves `./ui/Marks` to the `.ts` one and typecheck fails (TS1149) for every importer (release-ledger 2026-10-15, all three UI builders hit it).
- A UI port measures under bp's own rules: `.bp button { font: inherit }` outranks a one-class button rule (raise it under the surface's root class), and bp scales its UI by `1 + 0.5*(clamp(min(w/1280, h/800),1,2)-1)` (1.0625 at 1600x900), so compare widths at 1600x800 where the scale is 1.
- A contest port is held by `scripts/fidelity/` (style-contract roles + drive.py on the winner's own data): rerun it after any ledger CSS change; the arena's winner copy and its data must stay (do not `contest.mjs wrap --apply` release-manager while the contract is in use).
- A custom lens manifest for real products (`docs/standard/lenses-custom/`) must also pass lens-scan's `structure.mjs lens-add`, whose glyph check is stricter than bp's (absolute path commands only): 3 of 4 takeover lenses passed bp's gates and were refused at the product (2026-10-18). Run lens-add on a scratch structure as a gate.

## Question taste

- The operator keeps compound sparks whole: offer the split once, never re-ask it.
- Name a real target repo as an option when the work needs real data. The operator chose Personas through "Other" here.
- The operator accepts the Recommended option on most architecture forks. Spend questions on scope and target, not on convention.
- Skill names: the operator renames generic skill names to say what they serve (/adopt -> /adopt-bp). Offer a scoped name first.
- When options trade scope or safety for speed, the operator picks more and faster: all 4 ledger prototypes (asked for 3), `--dangerously-skip-permissions` over a scoped allow-list, chat onboarding over a draft card. Offer the bigger option explicitly, and write its condition (the risk) into the option text.

- Partial-scope picks: the operator drops Recommended extras that do not serve the flow they have in mind (picked only "selection from the ledger" for partial scans). Offer scope options as independent, not as a bundle.
- The operator chose the most capable model and the full option set again (Opus judgement, all four registry-execute behaviours, a free icon per lens, build in one go). For data ownership (another tool's file, Personas' context map) they want it done through the owning tool, not patched.
- When a contest winner is chosen for its look ("styling approach and typography strategy"), the owner wants its own fonts and colours too, over the product's palette: they overrode the Recommended bp fonts. Ask the family/palette question in wave 1 of a port, with the winner's option first.
- On a takeover the operator took the full scope at every fork (all four lens boosts, every output, build all of it) and overrode two Recommendeds: judge-heavy metrics over native tools, and merge to the real master over keeping fixes on the clone. At landing they fast-forwarded with a known dirty lockfile rather than wait. Give delegation options ("the Director gates /perfect for me") explicitly; they take them.

- The operator rewrites an option set that forces a false choice: asked "what does both latest mean", they answered "both model types available to select, one model per wave" - none of my three options. When a question offers variants of ONE mechanism (A/B arms, review, escalation), check first whether the plain reading ("both are choosable") is missing from the list.

- For VR the operator overrode the Recommended WebXR with the native route a sibling repo already proved (Unreal 5.8 + Meta XR, mage-arena), and added a structural doctrine (monorepo, logic once) via "Other". When a sibling repo has verified a toolchain on the target machine, offer it first and pair it with the sharing architecture it implies.
